## 第 8 步的发现

1. **flash 够用而且快**：样本三轮 56/56、55/56、56/56；真实项目 7 批 2 分 13 秒。v4-pro 同一项目要 20 分钟左右。倾向把默认模型换成 `deepseek-flash`，等真实数据两边对比完再定。
2. **任务粒度太粗**：真实项目里计划写着 Task 1、Task 2、Task 3，flash 把它们全归进一个“MVP”任务。要改提示词（v3）：一个任务是可以单独验收的交付；计划里编号的任务是不同任务；修复、补测试、审查归到它针对的那个任务。
3. **协调者派发的消息被当成“用户”**：Orca 这类编排工具派给 worker 的指令在会话里是 user 角色。目前只影响“开始执行”这类证据，不会让任务变成已完成，可以先不管，记为已知限制。
4. **工具报错里的计划文本**被引用成规划项，但因为不是用户说的，引擎自动降为 AI 建议，没有进入范围。说明降级规则在真实数据上起作用了。

## 环境和坑

- 运行：Node 22.18+，`npm run gongpai -- help`。`.env` 放 `DEEPSEEK_API_KEY` 和 `GONGPAI_MODEL`，不提交。
- Claude Code 命令行也可以当模型，但要 `env -u ANTHROPIC_API_KEY`，见 `docs/contracts.md`。
- Node 直接跑 TypeScript，不支持构造函数参数属性、enum 这类要编译的语法（`erasableSyntaxOnly`）。
- 全局 git pre-commit 钩子：同一个提交里既改已有测试文件、又改源码会被拦。新增测试文件不受影响。要改旧测试就单独提交。
- 页面服务只监听 127.0.0.1；写操作必须带 `x-gongpai: 1` 请求头。
- 第一次在页面上同步会弹出“发送说明”，同意后才调用模型；命令行 `extract` 直接整理，会打印一行说明。
