## MVP 是什么

一个同步命令加一个本地网页。同步命令读 Claude Code 和 Codex 的会话文件，加上粘贴导入，用一次大模型调用把新消息整理成带原话出处的证据，再由代码算出任务状态。网页用一屏显示目标、上次停在哪、需要你处理的事、下一步和任务列表，点任何一条看原话，点"继续"复制续接背景。

## 前提和假设

- 技术栈（开工时定）：TypeScript，由 Node 22 直接运行，不需要编译；数据库用 Node 自带的 `node:sqlite`，测试用 `node:test`，服务器用 `node:http`；页面是原生 HTML 和 JavaScript，没有构建步骤。唯一的运行依赖是 zod，用来校验大模型输出。这样队友拿到代码就能跑，没有构建链要学。
- 大模型只在第 6 步出现。测试阶段用 DeepSeek（`deepseek-v4-pro`，在 `.env` 里固定版本）。Claude Code 命令行也验证过可以当模型用，命令记在 `docs/contracts.md`。
- 下一步推荐只从待验证、进行中、待开始里挑；受阻的任务放在"需要你处理"里，不占下一步的名额。这是按需求文档 F09 的验收例子定的。
- 这次不做：浏览器扩展、Cursor、后台自动同步、来源冲突展示、消息编辑版本、团队权限、考勤费用。

- **产出**：`src/db/schema.sql`、`src/db/index.ts`、`tests/db.test.ts`

  期望：同一条消息按来源键写两次，只有一行；删除项目后，所有关联表里这个项目的数据都是 0 行。
- **不做**：迁移工具。表结构变了就重建数据库，数据可以重新同步。

## 第 2 步：读取 Claude Code

- **做什么**：
  - 读 `~/.claude/projects/*/*.jsonl`，只处理 user 和 assistant 两类行。
  - 用户的字符串正文保留；`isMeta` 为真的行丢掉。
  - AI 的 text 块保留，thinking 和 tool_use 丢掉。
  - tool_result 只保留出错的那些，截到 500 字，角色记为 tool_error。
  - 来源键用每行的 uuid，会话用 sessionId，另外记下时间和工作目录。
  - 子 agent 的会话文件在更深一层目录，这一版跳过。
- **项目归属**：工作目录经 `git rev-parse --show-toplevel` 得到仓库根目录，再到 project_dirs 里找对应项目。找不到的会话进待归类，不猜。
- **增量**：每个文件记下已读到的字节位置，下次从这里接着读。
- **产出**：`src/ingest/claude-code.ts`、`src/ingest/project.ts`、`src/cli/sync.ts`、`tests/fixtures/cc-sample.jsonl`，样本从真实文件里截取并脱敏。
- **怎么验**：
  ```
  npm run sync -- --source claude-code
  npm run sync -- --source claude-code
  ```
  期望：两次跑完，消息总数一样。往样本里追加一行再跑，多出一条。把样本改成无法解析的格式，命令提示"格式异常"，已有数据不动。

## 第 3 步：读取 Codex

- **做什么**：
  - 读 `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`。第一行 session_meta 取会话编号、工作目录和版本。
  - 只处理 `response_item` 里 type 为 message 的行；developer 角色丢掉。
  - 用户消息里有自动注入的块要过滤，开头是 `<environment_context>`、`<in-app-browser-context`、`# AGENTS.md instructions` 的都是。
  - 以 `# Files mentioned by the user` 开头的消息，只取 `## My request:` 后面的部分。
  - 工具输出只保留报错的。来源键用"会话编号加 ordinal"。
- **产出**：`src/ingest/codex.ts`、`tests/fixtures/codex-sample.jsonl`
- **怎么验**：检查和第 2 步一样。另外，同一目录下的 Claude Code 会话和 Codex 会话，必须归到同一个项目。

## 第 4 步：粘贴导入

- **做什么**：
  - 接收一段文本或 Markdown，按"你：""用户：""AI：""User:""Assistant:"这些标记切分发言。
  - 切不出来时整段算一条，交给用户在页面上修正发言者。
  - 原始时间一律记为空，只记采集时间。
  - 来源键用会话、顺序和正文的指纹。
- **产出**：`src/ingest/paste.ts`、页面上的导入入口，可以放到第 7 步再接上。
- **怎么验**：同一段文本导入两次，没有重复；页面上改过的发言者，重新同步后还在。

## 第 5 步：记忆引擎（纯代码，不碰大模型）

- **做什么**：四个纯函数，输入是证据列表和修正记录，输出是新状态。
  - `engine/state.ts`：按设计方案第 6 节的转换表算任务状态和状态变化记录。
  - `engine/plan.ts`：从引用了用户消息的规划证据生成规划版本；AI 提议的内容进建议区。
  - `engine/next.ts`：按"解除阻塞、验证产出、推进依赖已满足的任务"的顺序，挑最多三条下一步。
  - `engine/context.ts`：按模板拼续接上下文，已取消的事项单列为"不要做"。
- **产出**：上面四个文件，以及 `samples/*/ideal-evidence.json`（手写的"理想整理结果"）和 `tests/engine.test.ts`。
- **怎么验**：
  ```
  npm test -- engine
  ```
  期望：六个样本，用理想证据跑引擎，结果和预期完全一致。硬红线逐条有断言：
  - AI 自述完成不会让任务变成已完成；
  - 失败后重开原任务，不新增任务；
  - 已取消的事项不出现在下一步里；
  - 没有规划时输出"当前已读取记录中未发现明确规划"；
  - 续接上下文的"本轮请做"里没有已取消的事项；
  - 人工修正不会被新证据覆盖，冲突的证据进待确认。

先有理想证据，再接大模型，这样引擎的对错和大模型的好坏分得开。

## 第 6 步：证据整理（唯一的大模型调用）

- **做什么**：
  - 提示词放在 `prompts/evidence.md`，文件头写版本号。
  - 按会话取新消息。太长就按轮次切成几批，按顺序处理，后一批带上前一批之后的任务清单。
  - 输入包括：这批消息（带编号和角色）、项目当前的任务清单、当前规划、修正记录。
  - 输出按附录的证据结构，用 Zod 校验，不合格的重试一次，仍不合格就记失败，不猜。
  - 四道代码校验：
    - 引用的消息编号必须存在；
    - 说话人从被引用的消息里取；
    - "用户确认完成"和"规划项"必须引用用户消息，否则降级；
    - 和修正记录冲突的证据进待确认。
  - 每条证据记下模型版本和提示词版本。同一批消息、同一提示词版本、同一模型的结果缓存下来，重跑不重复写入。
- **产出**：`prompts/evidence.md`、`src/extract/schema.ts`、`src/extract/run.ts`、`src/extract/validate.ts`、`scripts/eval.ts`
- **怎么验**：
  ```
  npm run eval
  ```
  期望：打印一张表，每个样本一行，列出最终状态是否和预期一致、每条硬红线是否通过，另附不一致的明细。**过关条件是硬红线全部通过**。其余不一致逐条看，决定改提示词还是改样本。这里不设准确率门槛：样本太少，定了也没有依据。

## 第 7 步：页面

- **做什么**：
  - 概览页：当前目标、上次停在哪、需要你处理、下一步、任务列表、最近决定。
  - 原文侧栏：点任何结论都显示原话、来源、时间和覆盖范围。
  - 继续浮层：可以勾选、删改，然后复制，复制后状态只记"已复制"。
  - 待确认页：未归属的会话、拿不准的归并、冲突，每种都能处理。
  - 接入设置：一张表，列出每个来源是否读到对话、最后同步时间、读到多少个会话。另有同步按钮和粘贴导入入口。
  - 页面上的所有操作都写成修正记录。
- **先后**：先用第 0 步的样本数据灌库画页面，第 6 步接通后再换成真实数据。
- **产出**：`app/` 下的页面和接口。
- **怎么验**：打开本地页面，样本项目能完整显示；任意点一条结论，都能看到原话；首页的数字和数据库直接查出来的一样（写一个测试比对）；在页面上改过状态，重新同步后还在。

## 第 8 步：真实数据跑通

- **做什么**：用团队这次开发自己的会话跑一遍，包括 Claude Code、Codex，再粘贴一段网页 AI 的讨论。
- **怎么验**：
  - 找一个没参与某任务的队友，只看概览页，说出这个任务的状态和下一步。
  - 对一个任务点"继续"，把内容粘进另一个工具的新会话，对方能接着干。
  - 记下这一轮人工修正了几处。这是之后改提示词的依据。

## 第 9 步：收尾和演示

- 删除项目时清掉所有关联数据；每个来源能单独停止采集。
- 开启远程模型前提示会发送哪些内容。
- 按设计方案里的演示脚本彩排，确认每一步都能在现场复现。

## 附录一：契约

### 统一消息

```ts
type Message = {
  id: string                 // 来源稳定键：cc:<uuid> | cx:<会话编号>:<ordinal> | im:<指纹>
  source: 'claude_code' | 'codex' | 'import'
  sessionId: string
  projectId: string | null   // null 表示待归类
  seq: number                // 会话内顺序
  role: 'user' | 'assistant' | 'tool_error'
  text: string
  ts: string | null          // 原始时间，拿不到为 null，不伪造
  capturedAt: string         // 采集时间
  cwd: string | null
}
```

### 证据

```ts
const Evidence = z.object({
  reasoning: z.string(),                        // 判断理由，放在最前
  task: z.union([
    z.object({ id: z.string() }),               // 已有任务
    z.object({ newName: z.string(), goal: z.string() }),
    z.literal('unknown'),                       // 拿不准，进待确认
  ]),
  kind: z.enum([
    'plan_item', 'plan_add', 'plan_cancel',
    'started', 'ai_claims_done', 'user_confirms_done', 'failure',
    'blocked', 'unblocked',
    'decision_adopt', 'decision_reject',
    'out_of_scope', 'unrelated',
  ]),
  cite: z.array(z.string()).min(1),             // 引用的消息编号
  detail: z.string(),                           // 一句话
  reason: z.string().default('未说明'),          // 决定和取消的原因，原文没说就是"未说明"
})
```

### 任务状态

```ts
type TaskStatus = 'pending_confirm' | 'todo' | 'doing' | 'to_verify' | 'done' | 'blocked' | 'cancelled'
type DoneBasis = 'user_confirmed' | 'condition_met'   // 首版只用 user_confirmed
```

### 表

projects、project_dirs、sources、sessions、messages、sync_cursors、tasks、task_history、evidence、plan_versions、plan_items、decisions、suggestions、corrections、context_snapshots。关联表都设置删除级联，删项目时一起清掉。

## 附录二：六个样本场景

| 编号 | 场景 | 预期里必须写明的 |
|---|---|---|
| S1 | 先定四项规划，后来取消一项、新增一项 | 两个规划版本；取消项是已取消，且不出现在下一步 |
| S2 | 同一功能分别在 Codex 实现、Claude Code 修复、Claude Code 补测试 | 只算一个任务，挂着三段会话 |
| S3 | 从没定过规划，边聊边做了三件事 | 三个任务；规划显示"未发现明确规划" |
| S4 | AI 说完成，用户说打不开，修好后 AI 又说完成 | 最终是待验证；完成事件为 0；状态历史四条 |
| S5 | 旧会话太长，要换工具继续某任务 | 续接上下文只含这个任务，已取消的事项在"不要做"里 |
| S6 | 粘贴的对话只有后半段 | 覆盖标记为部分；不输出"从未规划" |

示例业务用中性的，比如记账小程序，不用 AI 店长。
