# 约定

代码里的唯一依据是 `src/contracts.ts`，这里只说明设计意图。

## 三层数据

1. **消息**：采集层产出。每条消息的 `id` 用来源自带的稳定编号，重复同步靠它去重。原始时间拿不到就是 `null`，另存采集时间。
2. **证据**：整理层产出，也是全项目唯一用到大模型的地方。一条证据说的是"某几条消息表明某个任务发生了某件事"，必须引用消息编号。
3. **视图**：记忆引擎把全部证据和人工修正按时间折叠出来，包括任务状态、规划版本、决定、待确认、下一步。视图随时可以重算，所以删除一条误归类的记录后，重算一次就好。

## 代码替大模型把的关

- 引用的消息编号必须真实存在，否则丢弃这条证据。
- 说话人由代码从被引用的消息里取。
- "用户确认完成""规划项""规划变更"必须引用至少一条用户消息，否则降级：确认完成降为 AI 自述，规划类降为 AI 建议，进待确认。
- 任务名和已有任务同名时，自动归到已有任务。
- 人工修正优先。修正之后新来的证据如果要改同一个任务的状态，不直接生效，进待确认。

## 状态怎么变

| 证据 | 结果 |
|---|---|
| 规划项、规划新增 | 新任务为待开始 |
| 开始执行 | 进行中（已完成的任务视为重开） |
| AI 称完成 | 待验证，不计完成 |
| 用户确认完成 | 已完成，记一次完成事件 |
| 报告失败 | 进行中（从待验证或已完成重开） |
| 受阻 | 受阻，记下缺什么 |
| 阻塞解除 | 进行中 |
| 规划取消 | 已取消，退出下一步 |

## 模型

- 测试用 DeepSeek，`.env` 里的 `GONGPAI_MODEL` 固定版本，每条证据都记下模型和提示词版本。
- 备选：本机已登录的 Claude Code 也可以当模型，已验证可用：
  ```
  env -u ANTHROPIC_API_KEY claude -p --output-format json --no-session-persistence \
    --model claude-opus-5 --tools "" --json-schema '<结构>'
  ```
  注意要去掉 `ANTHROPIC_API_KEY`，否则它优先用 API 密钥而不是登录。
